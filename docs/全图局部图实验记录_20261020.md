# 全图与局部图输入策略：实施与实测记录

日期：2026-10-20。图片：`/Users/gjz/Pictures/检测2.png`，方向校正后为 2006×1486 像素。

## 1. 已完成的实现

- 单模型、一次请求中可发送全图和一张原图裁剪；默认关闭，不改变原有命令的单图行为。
- CLI 参数 `--detail-crop` 和 HTTP 表单字段 `detail_crop` 支持 `off`、`auto`、手工整图 0–1000 坐标。
- 主流程只解码原图一次，复用图像进行质量分析、全图缩放和局部图编码；修复极小图片裁剪越界，拒绝非有限、越界及反向的手工坐标。
- 强调先用全图理解空间、再以局部图辅助细节，违规框仍按整张原图输出；沿用模型安全判断、真实法规目录核验与标准 JSON。
- 模型请求增加整体异步期限，避免仅靠 HTTPX 分阶段超时；预处理后按剩余预算发起请求，不自动重试。API 保留模型超时的结构化错误并返回 HTTP 504。
- 新增 `compare_image_inputs.py`，交错运行成对实验，记录成功、失败、分段时间及进程墙钟，保存逐次 JSON 和 Markdown 汇总。

这是 Monkey 的全局与局部信息思路在现有 API 输入上的迁移，不是完整模型训练复现。未接入新的目标检测器或 RelateAnything，也未更改真实 API 密钥及 GitHub 远程内容。

## 3. 各阶段实测

单位：秒。脚本总时间从图片预处理之前计至报告格式化；进程墙钟还包含 Python 启动、终端 JSON 序列化等开销，不含 HTTP 客户端上传回传。

| 轮次 | 输入 | 预处理 | DeepSeek请求 | 解析、法规及坐标 | 脚本总时间 | 进程墙钟 |
|---|---|---:|---:|---:|---:|---:|
| 1 | 全图 | 0.1246 | 6.4988 | 0.0043 | 6.6277 | 6.7873 |

两组均 3/3 次成功并在 8 秒内返回有效 JSON。全图进程墙钟中位数 5.8858 秒，最大 6.7873 秒；双图中位数 4.2081 秒，最大 6.8999 秒。局部图组预处理约多 0.02–0.03 秒。

双图后两轮更快，但首轮略慢；输出风险条数及文本长度不同、网络排队和服务状态均可能影响耗时，不能推断双图必然加速。各组仅三次，不估计稳定 p95，也不能保证真实视频 HTTP 链路每次都在八秒内完成。

## 4. 识别结果与人工观察

两组的六次结果均包含一条 `CLEAR` 电缆拖地风险，匹配本地条款：

> 《建筑与市政工程施工现场临时用电安全技术标准》JGJ/T 46-2024 第6.2.3条：电缆线路应采用埋地或架空敷设，严禁沿地面明设，并应避免机械损伤和介质腐蚀。

条款来源和本地核验日期保留在逐次 JSON。该记录属于本地目录核验，不能等同本次实时查询官方现行状态。

| 轮次 | 全图组：电缆以外的输出 | 双图组：电缆以外的输出 |
|---|---|---|
| 1 | 门锁疑似未锁闭，最终 NOT_ASSESSABLE | 门未上锁，最终 SUSPECTED |
| 2 | 门未上锁，最终 SUSPECTED | 无额外风险项 |
| 3 | 门未上锁，最终 SUSPECTED | 无额外风险项 |

人工观察原图可以看到双门闭合及门上的锁具 / 把手结构。仅因“没有独立挂锁”就推断没有有效锁闭，证据不足；同时静态外观也不能直接证明锁芯的实际机械状态。因此不能把模型输出的“锁闭状态”当作已经现场验证的安全事实。

双图组涉及锁闭问题的疑似 / 无法判断项由全图的 3/3 次减少到 1/3 次，属于初步改善迹象；NOT_ASSESSABLE 本身是在表达未知，并不等于已经误报明确违规。双图第一轮仍有“未挂锁”的推断，后两轮对象描述又直接断言锁闭，说明细粒度状态不确定性仍存在，不能声称误判问题已解决。

六次风险框均按整图像素返回，位于图像边界内；电缆框大致覆盖箱体下方区域。但尚未建立人工标准框并计算 IoU，不评价为高精度定位，也未验证跨场景完整召回。

## 5. 采用决策与限制

保留默认 `DETAIL_CROP=off`，将双图作为可显式启用的实验选项。当前自动选区基于边缘纹理，在这张图可能偏向背景，不作为已完成的目标识别算法。

当前手工框只验证局部细节是否可能有用，不能代表自动选区能力。下一阶段应使用跨场景人工标注集验证自动选区、状态正确率、风险召回和范围框，不能继续只围绕这一张配电箱图片调参。
